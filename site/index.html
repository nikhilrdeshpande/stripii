Before you download

Apple has not checked this app.

Stripii is not notarised, and it is ad-hoc signed rather than signed with an Apple Developer ID. Apple has not scanned it, and macOS cannot tell you who built it. macOS will say it cannot verify the app. That warning is accurate. Opening it anyway means trusting this download and me.

  1. 1

    Open the .dmg and drag Stripii to Applications.

  2. 2

    Open Stripii once. macOS says it can't be verified. Click Done.

  3. 3

    System Settings → Privacy & Security. Scroll down, click Open Anyway next to Stripii, and confirm.

Check the download before you open it

1. In Terminal, in the folder you downloaded to, run

cd ~/Downloads
shasum -a 256 Stripii-0.3.0.dmg

2. It should print exactly this

0fbbc4954c1db495b0f3ae6f7f1017f3f27fae66f720e6485d1bafa5ecc49fde  Stripii-0.3.0.dmg

This shows your file is the one published on the release page. It does not show that the software is safe.

Instead of step 3, in Terminal

xattr -dr com.apple.quarantine /Applications/Stripii.app

This removes the download flag, so macOS stops asking. Only do it after the checksum matches.

You may see one more prompt: macOS asking whether Stripii may use the “Stripii saved details key” in your Keychain. That key unlocks the names and numbers you save. Because the app is ad-hoc signed, each new version looks new to macOS, so it asks again after an update. Click Always Allow to stop it asking for this version.

How it works.
Step three is the one that matters.

01

Drop it in

PDFs, scans and photos, including iPhone HEIC. Text comes from the PDF where it has some, and from Apple's on-device Vision where it does not.

02

Details come out

Every page is redrawn with black boxes burned into the image. Annotations, form fields and embedded metadata go, including the location stored in photos.

03

It reads its own work back

Stripii runs text recognition over the finished page and runs every detector again. Ready means the read-back check found no remaining identifiers it recognises. Matches found with lower confidence are outlined for review. If a detected value can still be read, the result is held instead of handed over.

It cannot flag what it does not recognise, such as a surname in a sentence with no label. The known limits

In this synthetic photo one name was detected with lower confidence, so the file is marked for checking.

04

Fix what it missed

Click an outlined spot, or drag over anything else. The page is read back again before it is released.

05

Copy or save

Save a redacted PDF or copy the redacted text. The PDF is a flat image, so it has no searchable text. The copied text stays on this Mac, saved files get a plain name, and you are warned before saving into a cloud folder.

Tip

Tell it your own names once

Open Always Removed in the sidebar, or Stripii → Settings, and add your name, your family’s names and your account numbers. Stripii looks for them in every document after that. This is the best way to reduce misses in your own documents.

The list is encrypted on this Mac, and the key is kept in your Keychain.

Don't trust me.
Check.

You can check what macOS will allow the app to do. Run this after installing:

% codesign -d --entitlements - /Applications/Stripii.app
[Key] com.apple.security.app-sandbox
[Value]
    [Bool] true
[Key] com.apple.security.files.user-selected.read-write
[Value]
    [Bool] true

These two entitlements turn on the App Sandbox and give access to the files you select. Neither is a network entitlement, so macOS refuses every connection the app or its helper tries to make. That was tested inside the built app for DNS, TCP, HTTPS and a localhost listener.

This shows the permissions the app declares. Like the checksum, it is a narrow check, and it does not prove the software is safe.

The receipts.
Including the ones that don't flatter it.

14

findings in a security review of the engine before release. All fixed.

The worst: images inside ordinary text-layer PDFs were not being redacted at all, and the document was still graded ready to share. A scan pasted into a Word file went through untouched while the tool said it was safe.

The fix is the read-back. Those pages now go through text recognition and every detector runs again on the output. CI runs pip-audit on every change. What the review fixed

92.7%

of 688 labelled identifiers found, in an 84-document synthetic test set. Not 100%.

The documents were written to test it, so real documents may score differently. The benchmark and its caveats

Names in running prose without a label can slip through, and so can a description that identifies somebody without naming them.

Save names and numbers to help Stripii recognise them in future documents. That can reduce misses in your own documents. It does nothing for names it has never been told.

De-identification is not compliance. The health profile implements the HIPAA Safe Harbor identifier list, which is a method, not a certification.

Questions

Why a Mac app and not a website?

Stripii processes documents locally in a native Mac app, so that macOS itself can block it from the network. A web page that runs in your browser could also work offline, but nothing would stop a later version of the page from sending something.

A local web interface inside the app did not work either: WebKit will not render inside a sandbox with no network access. So the interface is native SwiftUI.

Why does macOS say it cannot verify the app?

Because it is not notarised. It is ad-hoc signed, without an Apple Developer ID, so Apple has not scanned it for malware and macOS cannot confirm who made it. You are being asked to trust the download itself.

Two checks help, and each answers a narrower question. The checksum shows your file matches the one on the release page. The codesign command shows the sandbox permissions the app declares. Neither shows that the software is safe.

Intel Mac? Windows?

No. There is a build for Apple silicon Macs only.

What does it cost?

Nothing. No account, no sign-up, no paid tier.

Is the app open source?

The engine and the command line tool are, under MIT, and the app runs that same engine. The Mac app's own source is closed for now.

What does this page collect?

Nothing. No cookies, no analytics, no scripts, and nothing loaded from anyone else's server. It is hosted on GitHub Pages, so GitHub receives each request the way any web host would. The page's source is in the repository.
